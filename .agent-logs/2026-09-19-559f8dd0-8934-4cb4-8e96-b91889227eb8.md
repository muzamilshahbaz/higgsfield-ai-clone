## Step 2 — Capture mechanism installed

Three things now exist in the repo root, and nothing else was touched:

| File | Role |
|---|---|
| [.claude/settings.json](.claude/settings.json) | Registers four lifecycle hooks with the harness |
| [.claude/hooks/capture.js](.claude/hooks/capture.js) | The capture script (Node, no dependencies) |
| `.agent-logs/` | Where session logs are written |

**How it works.** All four events — `SessionStart`, `UserPromptSubmit`, `Stop`, `SessionEnd` — run the same script. Rather than appending line by line, each run does a **full deterministic rebuild** of the log from the session transcript. That choice matters: the hook is idempotent, a missed or interrupted event is repaired by the next run, and sessions that predate the install get backfilled automatically.

The hooks use the schema's `args` exec form (`"command": "node"`, `"args": [...]`), so the script is spawned directly with no shell in between — no Windows quoting hazards in either PowerShell or Git Bash.

**Filtering is structural, not best-effort.** The script keeps `content[].type === "text"` from non-sidechain assistant records and user records that aren't `tool_result`/`isMeta`. Thinking blocks, tool calls, tool results, subagent traffic, attachments and system reminders are never in the set it reads from.
